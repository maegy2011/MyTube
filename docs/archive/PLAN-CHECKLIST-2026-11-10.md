## 1) IMPLEMENTATION — البنية والأسلوب والميت

**الوضع:** نمط قائم بحكم الأمر الواقع: `MainActivity` God-Activity (حالة + منطق + تنقل)، مستودع `YouTubeRepo` (IO)، `PlaylistDb` (Room)، شاشات UI خالصة. لا style-guide مكتوب؛ التعليقات العربية المختلطة تعمل كتوثيق قرارات.
1. **معمارية مُعلنة:** كتابة `ARCHITECTURE.md` (صفحة واحدة): الطبقات الأربع (UI→MainActivity→Repo/DAO→Service)، اتجاه الاعتماد، قاعدة "لا شبكة في Composable، لا `withContext` في UI". أي كود جديد يُراجَع ضدها.
2. **God-Activity:** لا تفكيك بطولي — الفصل التدريجي المعتمد: استخراج `PlayerController` (applyQuality/lang/track) ثم `FeedController` (refreshFeed/trending) ككلاسات خالصة تُحقن بالـplayer/dao/prefs. كل استخراج = commit + تجميع أخضر + سلوك متماثل ميدانيًا.
3. **كنس الميت:** بحث `TODO/FIXME/Dead` + دوال بلا استدعاء (`grep` الاستخدام قبل الحذف)، وحذف `onLongClick={}` المتبقي (ممنوع أصلًا) وأي `import` ميت. التحقق: `compileDebugKotlin` + `lintDebug` بلا تحذيرات جديدة.
4. **ممنوع الالتفاف:** لا `@Suppress` جديد بلا تعليق سبب، ولا `commitAllowingStateLoss`، ولا `allowMainThreadQueries`.

## 2) ERROR HANDLING & LOGGING — المصفوفة الكاملة

**الوضع:** أخطاء سطحية موجودة (`searchError`، `playerError`، Toasts)، لكن الابتلاع `catch (_: Exception) {}` واسع، ولا سجل أعطال ميداني (لا Crashlytics — قرار واعٍ: تطبيق محلي بلا حسابات؛ البديل ملف سجل محلي اختياري).
1. **رسائل المستخدم:** جرد كل `toast`/`playerError`/`searchError` — كل رسالة تسمي الفعل والبديل ("تعذّر الجلب — تحقق من الاتصال وحاول") لا "حدث خطأ". نصوص ar/en معًا إجباريًا (درس `err_player_unavailable`).
2. **الأعطال غير المميتة عن بُعد:** لا إرسال تلقائي (خصوصية). البديل: زر "نسخ تقرير عطل" في الإعدادات يجمع (الخطوة الأخيرة + نوع الخطأ + إصدار التطبيق) للحافظة — المستخدم يرسله طوعًا.
3. **أسطر قابلة للتتبع:** تفكيك استدعاءات السلسلة الطويلة في `applyQuality` و`downloadPin` لخطوات مسماة — كل `catch` يذكر اسم الخطوة في الرسالة/السجل.
4. **مصفوفة الحالات (تُختبر ميدانيًا واحدة واحدة):**
   - بلا شبكة: البحث/الخلاصة/التعليقات/الترجمة → رسالة + retry، والدبابيس تعمل (وضع عدم الاتصال موجود — يُختبر: ثبّت → طيران → شغّل).
   - فشل API: NewPipe يُرجع `Page` فارغة/استثناء → نفس مسار الخطأ لا شاشة فارغة صامتة (مراجعة كل `?: return emptyList` هل يقابلها UI فارغ مُفسَّر).
   - شبكة بطيئة: بعد H2 المهلات تحكم — التحقق الميداني: throttling من أدوات المطور، والتأكد أن المؤشرات (loading/skeleton) تظهر قبل المهلة لا بعدها.
   - التدوير: `configChanges` يمنع إعادة الإنشاء (س:24) — التحقق: تدوير أثناء (تشغيل + بحث + حوار مفتوح + ملء شاشة) ولا فقدان حالة. `rememberSaveable` للاستعلام فقط — توسيعه لموضع القائمة `listState` إن ضاع عند التدوير في الاختبار.
   - رفض الأذونات: POST_NOTIFICATIONS (الإشعار يغيب بصمت مقبول — يُوثَّق)، تجاهل البطارية (التطبيق يعمل لكن الخلفية قد تُقتل — رسالة تفسيرية موجودة؟ إن لا تُضاف).
   - إدخال غير متوقع: بحث فارغ/رموز/روابط مباشرة في حقل البحث، استيراد ملف تالف (يُختبر ملف غير OPML — حاليًا `importSubscriptions` قد يعيد فارغًا بصمت → رسالة "ملف غير صالح").
   - حالات حدّية للبيانات: فيديو بلا ترجمات/بلا صوت/بث مباشر/عمر مقيد/محذوف أثناء التشغيل — كل فرع `null` في `stream()` يقابله UI مُفسَّر (اختبر بقائمة عناوين حدّية ثابتة).

## 3) USABILITY & ACCESSIBILITY — بلا مصمم، بالمعايير

**الوضع:** M3 يوتيوب-التصميم، ثيم داكن/فاتح/نظام موجود، RTL قسري، خطوط `.sp` (تتكيف مع حجم خط النظام ✅)، `contentDescription=null` على أيقونات زخرفية داخل صفوف لها نص (صحيح) — لكن يجب جرد الأزرار الأيقونية المنفردة (تشغيل/تقديم/إغلاق) أن لكلٍّ وصفًا منطوقًا.
1. **جرد إمكانية الوصول:** كل `IconButton` منفرد → `contentDescription` من `strings.xml` (لا نص مُصلَّب). اختبار TalkBack لمسار كامل (بحث → تشغيل → طابور) وتسجيل العوائق.
2. **الأحجام:** اختبار `fontScale=1.3` و`displaySize=large` على شاشة صغيرة (المحاكي 4.7"): لا قصّ في البطاقات/الحبوب/الحوارات. إصلاحها `minHeight`/`flexible` لا `fixed dp` جديد.
3. **الداكن/الفاتح:** لقطة لكل شاشة رئيسية بالوضعين — التباين AA مُتحقق للرموز (عمل سابق) ويُعاد للشاشات الجديدة (الإعدادات/القناة).
4. **التابلت:** غير مدعوم رسميًا — القرار: إعلان `smallScreens` فقط؟ إن بقي مفتوحًا، اختبار محاكي 10" وإصلاح الكارثي فقط (تمدد غير مقروء)، بلا تصميم مخصص.
5. **ممنوع الالتفاف:** لا `contentDescription=null` على زر وظيفي، ولا لون وحده ينقل معنى (الأحمر + نص دائمًا).

## 4) TESTING & TESTABILITY — من الصفر بصدق

**الوضع:** صفر اختبارات (`find *test*` فارغ). الكود الحالي غير قابل للاختبار (منطق داخل Composable/Activity).
1. **الترتيب الصحيح:** لا كتابة اختبارات للـGod-Activity — أولًا الاستخراج (بند 1.2) ينتج دوالًا خالصة (`escapeLike` نموذجًا — تُختبر اليوم)، ثم:
   - وحدة: `favKey`، `escapeLike`، `formatDuration`، `PinFiles.sha`، منطق `CommentPager.hasMore`، `pickAudioIdxFor` (يُستخرج خالصًا أولًا).
   - أدوات: `room` اختبار هجرة 1→7 على قاعدة حقيقية (يمنع كسر M1/M2 مستقبلًا).
2. **UI:** بعد استقرار الشاشات — اختبار Compose واحد لمسار البحث-النتائج (query → fake repo → قائمة) كحارس انحدار، لا تغطية شكلية.
3. **الحذف:** أي اختبار يغطي سلوكًا أُزيل يُحذف مع الـcommit نفسه (قاعدة: الكود والاختبار في نفس الـdiff).
4. **ممنوع الالتفاف:** لا هدف نسبة تغطية، لا اختبارات `assertTrue(true)`، لا `Thread.sleep` في الاختبارات (TestDispatcher).

## 5) PERFORMANCE — بالأرقام لا بالظن

**الوضع:** IO خارج الرئيسي ✅، LazyLists ✅، كاش Coil ✅، MediaCache ✅، prefetch محدود ✅. المجهول: إعادة التركيب، وصور القوائم.
1. **إعادة التركيب:** تشغيل `showRecompositionCounts`/Layout Inspector على (التمرير في الترند + تقدم المشغّل) — `playerPositionMs` كل 500ms يُعيد تركيب المشغّل؛ التأكد أن القوائم خارج نطاق القراءة (derivedState/نطاق ضيق). أي `mutableStateOf` يُقرأ في نطاق واسع يُضيَّق.
2. **التخصيص في الساخن:** `formatDuration`/`favKey` داخل `items{}` — تُحسب مرة عند البناء وتُخزَّن في `VideoItem` (حقل محسوب) بدل كل تركيبة.
3. **الشبكة:** `refreshFeed` يجلب N قنوات كل فتح — سياسة: خلاصة 6h موجودة ✅؛ يُضاف `If-None-Match`/ETag؟ (خلاصات يوتيوب RSS لا تدعم بقوة — القرار: الاحتفاظ بالكاش الحالي وتوثيق أنه السقف).
4. **القياس:** قبل/بعد كل تحسين: `adb shell dumpsys gfxinfo` (إطارات) + حجم APK + زمن بدء بارد (يُسجَّل في الملف).

## 6) DEPENDENCIES — حد أدنى صارم

**الجرد الحالي (19):** compose-bom، media3 (3)، coil، paging (2)، coroutines، okhttp، newpipe-extractor، room (3)، splash، lifecycle، activity-compose، icons-extended. لا مكتبة زائدة ظاهرة.
1. **القاعدة:** أي اعتماد جديد يحتاج مذكرة 3 أسطر (لماذا/الحجم/البديل اليدوي). مرشح الإزالة الوحيد اليوم: `icons-extended` (ضخم — يُستبدل بالأيقونات المستخدمة فعلًا كـvectors محلية إن تجاوزت مساهمتها 300KB في APK — يُقاس بـAPK Analyzer).
2. **الترقيات:** `NewPipeExtractor 0.26.5` مثبّت عمدًا — أي رفع = قراءة breaking-changes + تجميع + اختبار (بحث/بث/تعليقات/خلاصة) قبل الدمج، وpin الإصدار يبقى.
3. **R8:** release مُفعَّل + keep-rules لـNewPipe ✅ — التحقق: تجميع release (غير مشحون) بعد كل تغيير يعكس (extractor/reflect/serialization) وتشغيل دخاني عليه قبل أي نشر.

## 7) READABILITY — أسلوب مُلزم

1. **لامدا صريحة** حيث المعامل غامض (`it` المتداخلة في `mapNotNull` داخل `map` تُسمَّى)، **وسائط مسماة** في استدعاءات +5 وسائط (حبوب المشغّل/الشاشات)، **أنواع صريحة** على الدوال العامة و`remember` المعقدة، وحذف الزائد منها حيث التخمين بديهي.
2. **تعليقات:** كل `catch` صامت موجود يُبرَّر بسطر أو يُستبدل برسالة؛ التعليقات القديمة تُراجَع مع كل diff (درس `pageless first 30` الذي كذب بعد الترقية — القاعدة: التعليق الذي يصف سلوكًا يُحدَّث مع السلوك في نفس الـcommit).
3. **موارد:** `@StringRes` ونحوها على معاملات الـIDs، ولا نص عربي/إنجليزي مُصلَّب في Kotlin (جرد `grep '"[ء-غ]'` خارج `strings.xml` = صفر).
