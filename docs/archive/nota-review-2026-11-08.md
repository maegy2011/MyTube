# مراجعة MyTube الشاملة — بدون مجاملة (2026-11-08، v0.2.0 / vc20)

## الخلاصة الصادقة
تطبيق يعمل وحقق هدفه الأساسي (بحث + تشغيل صوتي + قوائم)، لكنه يعاني من **مرض معماري واحد يغذي كل العيوب**: كل شيء في ملف واحد (`MainActivity.kt` ≈ 2590 سطرًا، 63 حالة `mutableStateOf`، 12 شاشة `@Composable`) — بحث، مشغل، قائمة، قوائم محفوظة، إعدادات، رائج، إشعارات. هذا يجعل أي تعديل محفوفًا بالمخاطر ويُبطئ كل مراجعة قادمة. **التوصية الأولى والأهم: تقسيم الملف إلى شاشات وملفات مستقلة قبل أي ميزة جديدة.**

## 1. فنيًا (بنية وكود)
- **احتكار الملف الواحد**: 2590 سطرًا في `MainActivity.kt` مقابل 190 للـ Repo و133 للقاعدة. أي خطأ في شاشة يهدد التطبيق كله، والمراجعة تستغرق أضعافًا.
- **63 حالة محلية**: مبالغ فيه؛ حالات كثيرة كان يجب أن تعيش في `ViewModel` واحد (البحث/النتائج/الرائج/الإعدادات) لتنجو من تدوير الشاشة. حاليًا تدوير الجهاز أثناء البحث قد يفقد الحالة.
- **إيجابي**: سياسة عدم التشغيل التلقائي مطبقة بصرامة (`playWhenReady=false` قبل كل `prepare`)، والترحيل `1→2` آمن بلا مسح، ومنع التكرار في القوائم سليم.
- **دين تقني**: `fallbackToDestructiveMigration()` ما زال موجودًا بجانب الترحيل الآمن — أي نسخة قاعدة مستقبلية بلا ترحيل مكتوب **ستمسح بيانات المستخدمين**. يجب إزالته من نسخة الإصدار.
- **النطاق الزمني للقوائم**: لا يوجد `exportSchema` ولا اختبار ترحيل — أي خطأ في عمود مستقبلي = فقدان بيانات.

## 2. تقنيًا (أداء وموثوقية)
- **حلقة 500ms دائمة** (`while(true)` لجلب الموضع/المدة) تعمل حتى بدون تشغيل — تستهلك بطارية بلا داعٍ. يجب إيقافها عند `playing == null`.
- **بحث بلا إلغاء (debounce/cancel)**: كل حرف يضرب الشبكة؛ طلبات قديمة قد تصل متأخرة وتُظهر نتائج خاطئة. يلزم `debounce ~400ms` + إلغاء المهمة السابقة.
- **`version = "+"` للمستخرج**: نسخة NewPipe عائمة — بناء اليوم قد يختلف عن بناء الغد ويُدخل كسرًا صامتًا. ثبّت النسخة (`0.26.5` المختبرة).
- **إيجابي**: إلغاء التحميل الزائد عند التمرير (single-flight + صفحات) سليم، والتبديل للصوت عند الخلفية يحمي البطارية.

## 3. تجربة المستخدم والواجهة
- **إيجابي حقيقي**: شاشة البحث المستقلة + الرأس المدمج + التبويبات الممررة + شارة البلد — اتجاه يوتيوب الصحيح.
- **عيوب مباشرة**:
  - الرائج يُجلب مرة واحدة فقط عند فتح التطبيق؛ تغيير البلد لا يُحدّثه دائمًا إن كانت هناك نتائج معروضة.
  - لا توجد حالة "فارغ أنيق" للأخطاء الشبكية في الرائج (رسالة فقط، بلا زر إعادة).
  - أزرار المشغل مختلطة اللغات (عربي/إنجليزي) والصف الخارجي طويل — يحتاج اختصارًا حقيقيًا لا تمريرًا فقط.
  - زر الرجوع له 7 طبقات (بحث، إعدادات، قائمة، قوائم، مشغل، ملء شاشة، نتائج) — يعمل لكنه هش؛ أي ترتيب خاطئ يحبس المستخدم.

## 4. الميزات والوظائف الأساسية (core)
| موجود ويعمل | ناقص وضروري |
|---|---|
| بحث + اقتراحات + سجل | **إعادة المحاولة** لأي فشل شبكي (زر، لا رسالة فقط) |
| تشغيل صوتي افتراضي + جودات | **سجل استماع/مشاهدة** (أساس أي تطبيق فيديو) |
| قائمة صريحة بلا تكرار | **مفضلة بضغطة واحدة** (قلب، لا إضافة لقائمة كل مرة) |
| قوائم Room + إيموجي + ترحيل | **مزامنة/تصدير** القوائم (ملف، قبل فوات الأوان) |
| ترجمة وصوت بلغتين بديلتين | **مؤقت نوم** (تطبيق صوتي بلا مؤقت = عيب جوهري) |
| رائج حقيقي ببلد يدوي | **وضع عدم حفظ السجل** + مسح شامل |
| إشعار + خلفية + PiP | **تكرار A-B / سرعة التشغيل** الموعودة سابقًا |

## 5. أولويات الإصلاح (بالترتيب، بلا تسرع)
1. **تقسيم `MainActivity.kt`** إلى ملفات (بحث/مشغل/قوائم/إعدادات/رائج) — قبل أي ميزة.
2. **تثبيت نسخة المستخرج** + إزالة `fallbackToDestructiveMigration` من الإصدار.
3. **إلغاء بحث متجاوب** (debounce + cancel) + زر إعادة لكل فشل شبكي.
4. **إيقاف حلقة الـ500ms** عند عدم التشغيل + `ViewModel` يحفظ الحالة عند التدوير.
5. ثم فقط: مؤقت النوم + المفضلة + سجل الاستماع.

التقييم العام: **6.5/10** — أساس سليم واتجاه صحيح، لكن الملف الواحد والنواقص الأساسية الثلاثة (مؤقت/مفضلة/سجل) تمنعه من أن يكون تطبيقًا يوميًا حقيقيًا.
