## 1) IMPLEMENTATION — ما تبقى فعلًا

- **يؤدي وظيفته؟** كل إصلاح أخير له اختبار ميداني مسمّى على محمد (خلفية بعد خروج/H1، طيران/H2، إيقاف الترجمة/M3، `%`/M2، استيراد تالف/2.6). بلا ادعاء.
- **تبسيط حقيقي واحد:** `applyQuality` (~50 سطرًا، 4 فروع) — الاستخراج: `resolvePlaybackUrl(q, sd)` خالصة تُرجع `(url, isMerged)`، فيبقى في الأصل البناء+الدمج فقط. commit مستقل + تجميع + اختبار (صوت-فقط/مدمج/DASH).
- **لا اعتماد جديد، لا إطار ممنوع:** مؤكد (19 اعتمادًا، لا جديد منذ v0.2.2).
- **ما لم يُستخدم ويجب:** `StrictMode` في debug (يكشف أي IO تسرب للرئيسي مستقبلًا) — يُضاف في `MyTubeApp.onCreate` مقيدًا بـ`BuildConfig.DEBUG` + `penaltyLog` فقط (بلا crash).
- **التجريد:** المستوى صحيح (UI→منسق→مستودع)، والـGod-Activity مُوثق كدين تقني في `ARCHITECTURE.md` بخطة فصل — لا يُحل هنا.
- **تكرار موجود؟** نعم واحد مُوثق: `feedFor` (RSS) + `channelVideos` (تبويب) كبديل — ليس تكرارًا بل fallback مقصود بتعليق. `localizedTitle` و`suggestions` يتشاركان نمط "NewPipe ثم Google" — يُستخرج `getOrFallback(primary, secondary)` عام عند ثالث استخدام، لا الآن (قاعدة الثلاثة).
- **SOLID:** التقييم الصادق: SRP منتهَك في MainActivity (موثق ومجدول)، OCP محترم (callbacks لا تعديل)، LSP/ISP غير منطبقين (لا وراثة/واجهات)، DI يدوي عبر params (كافٍ لحجم التطبيق — Hilt مرفوض: تكلفة بلا عائد هنا).
- **الحل البديل الأفضل جوهريًا؟** لا — كل إصلاح نُفذ هو الحد الأدنى الصحيح (H1 سطر، H2 نمط قائم، M4 نمط Compose القياسي).

## 2) LOGIC ERRORS — حالات الكسر المتعمد

لكل إصلاح، حالة كسر مصممة تُختبر ميدانيًا (على محمد — لا محاكي):
- H1: خروج نهائي أثناء تشغيل + قتل الـActivity بالنظام (لا رجوع فقط).
- H2: throttling بسرعة 50kbps + انقطاع mid-request.
- H3: منع بدء الخدمة (إيقاف قسري قبل الفتح).
- M3 OFF: فيديو عنوانه بلغة نادرة بلا ترجمات أصلًا → يجب الأصل دائمًا.
- M2: بحث `%` و`_` و`\` وحدهم.
- زر التشخيص: ضغطه بلا أخطاء → تقرير "none" لا كراش.
- استيراد: ملف نصي عشوائي + OPML فارغ + OPML ضخم (1000 قناة).

## 3) ERROR HANDLING — المتبقي

- الطريقة صحيحة (مستخدم ar/en + فني اختياري عبر زر التشخيص). المتبقي: جرد `catch (_: Exception) { }` الفارغة تمامًا (بلا حتى تعليق) — `grep` يحصيها، وكل واحدة إما رسالة أو تعليق سبب مكتوب. الرقم المستهدف: صفر فارغة بلا توثيق.
- لا سجل تلقائي (قرار خصوصية موثق) — زر التشخيص هو البديل الكافي.

## 4) USABILITY — الواجهة بديهية؟

- زر التشخيص: موضعه بجانب "مسح الكاش" + وصفه يذكر الطوعية — كافٍ، لا يُنقل.
- API: لا API خارجي — التوثيق هو `ARCHITECTURE.md` + تعليقات القرارات. كافٍ.

## 8) SECURITY & PRIVACY — الفحص التفصيلي

- **بلا مصادقة/تفويض** (تطبيق محلي بلا حسابات) — لا سطح.
- **بلا أسرار** (تحقق سابق: لا مفاتيح/كلمات سر في APK).

- **مدخلات المستخدم:** البحث/الاستيراد/الترجمة — البحث يُمرَّر لمستخرج NewPipe (يُرمَّز داخليًا)، الاستيراد يُحلَّل كـXML عبر المستخرج (ملف خبيث = فشل آمن + رسالة جديدة ✅)، الترجمة عبر HTTPS ✅.

- **التشفير:** غير مطلوب (لا بيانات حساسة — مفضلة وقوائم محلية؛ النسخ الاحتياطي مشفر من جوجل نفسها).
